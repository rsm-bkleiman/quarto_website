Why Do Customers Stay Loyal?

A company surveys thousands of customers. Each person says whether they perceive the brand as trustworthy, easy to use, appealing, and so on. Each also rates their overall satisfaction on a 1-to-5 scale. Now the product team wants a simple answer: which of these nine perceptions actually moves the satisfaction needle?

This sounds simple, but the answer depends entirely on how you ask the question. A correlation coefficient captures raw association but ignores redundancy between predictors. A regression coefficient controls for everything else but becomes unstable when predictors are correlated. A random forest captures nonlinear relationships but is notoriously hard to interpret.

Key Drivers Analysis is a family of methods, not a single recipe. The goal of this post is to compute six of them side by side on the same data, understand what each one is really measuring, and discuss what happens when they disagree.

Method 1: Pearson Correlations

The simplest starting point. For each driver, compute the Pearson correlation with satisfaction.

What it measures: raw linear association, ignoring everything else.

Weakness: if two drivers are correlated with each other, they both get credit for the same shared variance. This inflates the apparent importance of redundant variables.

Method 2: Standardized Regression Coefficients

Fit a single OLS regression of satisfaction on all nine drivers simultaneously. Standardize all variables first (mean 0, sd 1) so that the coefficients are comparable across predictors.

What it measures: the partial effect of each driver, holding all others constant.

Weakness: when predictors are correlated (multicollinearity), coefficients become unstable and hard to interpret. A small coefficient might mean “genuinely unimportant” or might mean “highly redundant with another predictor.”

Method 3: Drop-One R² (Usefulness)

Also called “incremental R²” or “usefulness.” For each driver, measure how much R² drops when you remove that one driver from the full model.

\[\text{Usefulness}_j = R^2_{\text{full}} - R^2_{-j}\]

What it measures: the unique variance explained by each driver above and beyond all the others.

Weakness: this rewards predictors that are not correlated with others, which can penalize genuinely important but redundant attributes.

Method 4: Shapley Values (Custom Implementation)

Shapley values come from cooperative game theory. The idea: think of the nine predictors as players on a team. Each “coalition” (subset) of predictors gets a “payout” (the R² of the model using just those predictors). How do we fairly divide that payout among the individual players?

The Shapley value of predictor \(j\) is the average marginal contribution of \(j\) across all possible orderings in which the predictors could be added:

\[\phi_j = \sum_{S \subseteq N \setminus \{j\}} \frac{|S|!(|N|-|S|-1)!}{|N|!} \left[ R^2(S \cup \{j\}) - R^2(S) \right]\]

where \(N\) is the full set of predictors and \(S\) ranges over all subsets that do not include \(j\).

Key property: Shapley values always add up exactly to R². No credit is lost or double-counted.

Computation note: with 9 predictors there are \(2^9 = 512\) possible subsets. This is exactly computable by brute force, which is what we do below.

Show code 
def compute_r2_cache(X, y, feature_names):
    """Pre-compute R² for all 2^p subsets."""
    n_features = len(feature_names)
    r2_cache = {}
    for size in range(n_features + 1):
        for subset in combinations(range(n_features), size):
            if len(subset) == 0:
                r2_cache[subset] = 0.0
            else:
                X_sub = sm.add_constant(X[:, list(subset)])
                r2_cache[subset] = sm.OLS(y, X_sub).fit().rsquared
    return r2_cache

def shapley_values_linear(X, y, feature_names):
    """
    Exact Shapley values using R² as the value function.
    Enumerates all 2^p coalitions explicitly.
    Time complexity: O(2^p * p) model fits.
    """
    n = len(feature_names)
    r2_cache = compute_r2_cache(X, y, feature_names)

    shapley = {}
    for j in range(n):
        sv = 0.0
        others = [i for i in range(n) if i != j]
        for size in range(n):
            for subset in combinations(others, size):
                subset_with_j = tuple(sorted(subset + (j,)))
                weight = (
                    math.factorial(size) * math.factorial(n - size - 1)
                    / math.factorial(n)
                )
                sv += weight * (r2_cache[subset_with_j] - r2_cache[subset])
        shapley[feature_names[j]] = sv
    return shapley, r2_cache

shapley_raw, r2_cache = shapley_values_linear(X, y, drivers)
shapley_s = pd.Series({LABELS[k]: v for k, v in shapley_raw.items()}).sort_values(ascending=False)

How the Custom Code Works

The key insight is that we evaluate the model on every possible subset. For each predictor, we then calculate its average marginal contribution: how much did R² improve when we joined each possible coalition of teammates?

The weights ensure that each ordering (permutation) of predictors gets equal representation. A predictor that joins a large coalition gets the same total weight as one that joins a small coalition.

Method 5: Johnson’s Relative Weights

Johnson (2000) took a different approach to the multicollinearity problem. Instead of averaging over subsets, the idea is to:

  1. Rotate the predictors into an orthogonal basis via eigendecomposition of the correlation matrix
  2. Regress the outcome on these orthogonal “principal” predictors
  3. Map the variance explained by each principal predictor back to the original predictors, proportional to how much each original predictor loads on each principal component

The result: a set of weights that (a) sum to R² and (b) are less sensitive to multicollinearity than standardized betas.

Show code 
def johnsons_relative_weights(X, y):
    """
    Johnson (2000) relative weights via eigendecomposition of Rxx.
    Returns weights that sum to R².
    """
    sc_X = StandardScaler()
    sc_y = StandardScaler()
    X_s = sc_X.fit_transform(X)
    y_s = sc_y.fit_transform(y.reshape(-1, 1)).ravel()

    p = X_s.shape[1]
    Rxx = np.corrcoef(X_s.T)                   # p x p correlation matrix
    rxy = np.array([
        np.corrcoef(X_s[:, j], y_s)[0, 1] for j in range(p)
    ])                                          # correlations with y

    # Eigendecompose: Rxx = V diag(lambda) V^T
    eigvals, V = np.linalg.eigh(Rxx)
    eigvals = np.maximum(eigvals, 1e-10)        # numerical guard

    # OLS coefficients on X -> beta = Rxx^{-1} rxy
    # Then coefficients on orthogonal Z = XV: beta_z = V^T beta = Lambda^{-1} V^T rxy
    beta_ols = np.linalg.lstsq(Rxx, rxy, rcond=None)[0]
    beta_z = V.T @ beta_ols  # Lambda^{-1} V^T rxy

    # Relative weight for predictor j:
    # epsilon_j = sum_k (V[j,k] * sqrt(lambda[k]))^2 * beta_z[k]^2
    # This simplifies to sum_k V[j,k]^2 * (V^T rxy)[k]^2 / lambda[k]
    # and provably sums to R^2 = rxy^T Rxx^{-1} rxy
    rw = np.array([
        sum(
            (V[j, k] * np.sqrt(eigvals[k]))**2 * beta_z[k]**2
            for k in range(p)
        )
        for j in range(p)
    ])
    R2 = float(rxy @ beta_ols)
    return rw, R2

Johnson’s relative weights tell a notably different story: the weights are much more compressed, with Good Service edging out the others. This method tends to equalize drivers that are highly intercorrelated – they “share” their principal components more evenly. This is a feature, not a bug, when predictors are genuinely redundant signals of the same underlying construct.

Method 6: Random Forest – Mean Decrease in Gini

A gradient-free, nonparametric approach. Fit a random forest with many decision trees. At each node split, the chosen variable is the one that most reduces impurity (Gini impurity for classification; variance for regression). The mean decrease in Gini for variable \(j\) is the total reduction in impurity attributable to \(j\) across all trees and all nodes.

What it measures: overall predictive importance, including nonlinear effects and interactions.

Weakness: biased toward high-cardinality variables; can assign importance to spuriously correlated noise. Also not directly comparable to R² values from the other methods.

Bonus: Shapley Values for a Logistic Regression (GLM)

The medium challenge asked for a custom Shapley implementation – done above in Method 4. The harder challenge: extend Shapley to a generalized linear model (GLM).

Here I fit a logistic regression where the outcome is binary: is a customer highly satisfied (rating 4 or 5)? Instead of R², I use McFadden’s pseudo-R² as the value function:

\[\text{McFadden's} \ \rho^2 = 1 - \frac{\log L_{\text{model}}}{\log L_{\text{null}}}\]

This measures how much the predictors improve on a null model that predicts only the base rate.

Show code 
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import log_loss

# Create binary outcome: satisfied = 4 or 5
y_bin = (df['satisfaction'] >= 4).astype(int).values

def mcfadden_r2_logit(X_sub, y_bin):
    """McFadden pseudo-R² for logistic regression on given feature subset."""
    if X_sub.shape[1] == 0:
        return 0.0
    clf = LogisticRegression(max_iter=500, solver='lbfgs', C=1e6)
    clf.fit(X_sub, y_bin)
    p_hat = clf.predict_proba(X_sub)[:, 1]
    p_hat = np.clip(p_hat, 1e-9, 1 - 1e-9)
    ll_model = np.sum(y_bin * np.log(p_hat) + (1 - y_bin) * np.log(1 - p_hat))
    p_null = y_bin.mean()
    ll_null = len(y_bin) * (p_null * np.log(p_null) + (1 - p_null) * np.log(1 - p_null))
    return 1.0 - ll_model / ll_null

def shapley_values_glm(X, y_bin, feature_names, value_fn):
    """
    Exact Shapley values for any value function (e.g., McFadden pseudo-R²).
    Enumerates all 2^p coalitions.
    """
    n = len(feature_names)
    val_cache = {}
    for size in range(n + 1):
        for subset in combinations(range(n), size):
            if len(subset) == 0:
                val_cache[subset] = 0.0
            else:
                val_cache[subset] = value_fn(X[:, list(subset)], y_bin)

    shapley = {}
    for j in range(n):
        sv = 0.0
        others = [i for i in range(n) if i != j]
        for size in range(n):
            for subset in combinations(others, size):
                subset_with_j = tuple(sorted(subset + (j,)))
                weight = (
                    math.factorial(size) * math.factorial(n - size - 1)
                    / math.factorial(n)
                )
                sv += weight * (val_cache[subset_with_j] - val_cache[subset])
        shapley[feature_names[j]] = sv
    return shapley, val_cache

Takeaways

Method Signal type Handles multicollinearity? Captures nonlinearity?
Pearson r Raw association No No
Std. Beta Partial (net of others) Partially No
Drop-one R² Unique contribution Yes No
Shapley Fair allocation of shared variance Yes No
Johnson’s RW Eigenspace redistribution Yes No
RF Gini Predictive importance Yes Yes

Consistent winners across methods: Trust and Makes Impact are ranked in the top three by every method. If a brand wants to move satisfaction, these two perceptions are the safest bets.

Consistent laggards: Popular and Differs are near the bottom on almost every method. Even if customers perceive the brand as differentiated or popular, that perception does not translate into higher satisfaction.

Where methods diverge: Good Service is solidly top-three on linear methods but less dominant in the RF. Build Quality and Rewarding are elevated by the RF, possibly because their effect on satisfaction is nonlinear (e.g., a threshold effect that regression cannot capture). Johnson’s relative weights compress the spread, making all drivers look more similar than the other methods suggest.

The practical lesson: run multiple methods, then focus on the consensus top drivers. When methods disagree, that disagreement is a signal worth investigating – it suggests either nonlinearity, interactions, or a measurement issue with that driver.
